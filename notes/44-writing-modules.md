## ⚡ Core: the 10-minute version

**The idea.** A good module is like a good appliance: **few buttons, safe defaults, clear labels, hard to misuse**.

```
modules/s3-secure-bucket/
├── versions.tf      # required_providers with MINIMUM versions; NO provider blocks
├── variables.tf     # few inputs, typed, validated, documented
├── main.tf          # the resources, secure by default
├── outputs.tf       # what callers need (IDs, ARNs, names)
├── README.md        # generated by terraform-docs + a usage example
└── examples/basic/  # a runnable example (also used by tests)
```

```hcl
module "logs" {
  source      = "./modules/s3-secure-bucket"
  name        = "acme-logs"
  versioning  = true
  lifecycle_days = 90
}
```

**Picture it.** A kitchen appliance: inside there are motors and wires (resources); outside there are three buttons (variables) and a display (outputs). It won't let you open the door while it's running (validation), and it ships with the child lock on (secure defaults).

**The one thing to know.** **Don't put `provider` blocks in reusable modules.** Declare `required_providers` with a minimum version; the caller configures providers and passes them in.

**Try it now:** build the `s3-secure-bucket` module below and call it twice.

**You've got it if you can:** explain why a module shouldn't configure its provider, and list three rules for good module inputs.

## What it is

### File layout (the standard module structure)

| File / folder | Contents |
|---|---|
| `versions.tf` | `terraform { required_version, required_providers }` with **minimum** versions (`>= 6.0`) |
| `variables.tf` | Every input, with `type`, `description`, sensible `default`, `validation` |
| `main.tf` | Resources (split into more files if large: `iam.tf`, `logging.tf`) |
| `outputs.tf` | Every output, with `description` |
| `README.md` | What it does, a usage example, the inputs/outputs table (generated) |
| `examples/<name>/` | Small root modules showing real usage (and used by tests) |
| `tests/*.tftest.hcl` | Automated tests (topic 55) |
| `CHANGELOG.md` | What changed per version (topic 45) |

### Input design rules

| Rule | Why | Example |
|---|---|---|
| **Few inputs** | Every input is something a caller can get wrong. | Expose `versioning`, not 12 low-level settings. |
| **Typed precisely** | Errors at plan time, self-documenting. | `object({ days = number, storage_class = optional(string, "GLACIER") })` |
| **Validated** | Catch bad values with a clear message. | Bucket name regex. |
| **Secure by default** | Callers who don't think about security still get it. | Encryption on, public access blocked, TLS-only. |
| **Optional with `optional()` defaults** | Callers set only what they care about. | `optional(number, 30)` |
| **No "enable everything" flags** | Huge flag soup = untestable combinations. | Split into separate modules instead. |
| **Pass IDs in, don't look them up** | Modules that look things up by name are surprising and hard to reuse. | `vpc_id` as a variable, not `data "aws_vpc"` inside. |

### Output design rules

- Output what callers will **reference**: IDs, ARNs, names, endpoints.
- Every output gets a `description`.
- Output **stable, simple** values. Outputting a whole resource object (`value = aws_s3_bucket.this`) exposes internals and makes refactoring a breaking change.
- Mark secrets `sensitive = true` (or don't output them).

### Providers and modules

- Modules **inherit** the default provider configurations of their caller automatically.
- A module with its own `provider "aws" { region = ... }` block ⚠️:
  - can't be used with `count`/`for_each`/`depends_on`,
  - forces one region/account on every caller,
  - breaks badly when the module is removed (the provider config disappears with it, so Terraform can't destroy its resources).
- To use **non-default** (aliased) providers, the caller passes them:

```hcl
# in the module: declare that it expects two AWS configurations
terraform {
  required_providers {
    aws = {
      source                = "hashicorp/aws"
      version               = ">= 6.0"
      configuration_aliases = [aws.replica]     # "I need a second aws config called replica"
    }
  }
}

resource "aws_s3_bucket" "replica" {
  provider = aws.replica
  bucket   = "${var.name}-replica"
}
```

```hcl
# in the caller
module "logs" {
  source = "./modules/s3-replicated"
  providers = {
    aws         = aws              # the module's default aws = caller's default
    aws.replica = aws.virginia     # the module's aws.replica = caller's aws.virginia
  }
  name = "acme-logs"
}
```

### `count` / `for_each` on modules

```hcl
module "bucket" {
  source   = "./modules/s3-secure-bucket"
  for_each = toset(["logs", "artifacts", "backups"])
  name     = "acme-${each.key}"
}
```

Works only if the module has no `provider` blocks of its own (one more reason not to write them).

## Why it exists

Modules are code that **other people** run, often without reading it. A badly designed module spreads mistakes to every caller; a well-designed one spreads good practice. Most companies' Terraform quality is decided by the quality of a few shared modules.

---

## Analogy

**A kitchen appliance.**

- **Inside** (resources): motors, sensors, wiring. Users never see them.
- **Buttons** (variables): few, labelled, with sensible defaults ("normal wash").
- **Child lock on by default** (secure defaults): encryption, no public access.
- **Refuses dangerous settings** (validation): "temperature 400 °C not allowed".
- **Display** (outputs): "done", "time left": only what you need.
- **Power supply comes from the house** (providers come from the caller); an appliance with its own built-in generator (provider block) can only work in one place.

---

## How it works inside

- During `init`, Terraform merges **every** module's `required_providers`. Root says `~> 6.0`, module says `>= 6.0` → `6.x` is chosen. If a module said `< 6.0`, it would conflict (topic 10), which is why modules state **minimums**, not tight pins.
- The module's variables are evaluated in the **caller's** context (the `module` block's arguments), then the module's resources use them. `validation` runs before any resource in the module is planned.
- `configuration_aliases` tells Terraform "this module needs these provider names"; the `providers` map in the caller wires actual configurations to them.

## Code / commands

### The module: `~/tf-lab/modules/s3-secure-bucket/`

`versions.tf`:

```hcl
terraform {
  required_version = ">= 1.9"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 6.0"
    }
  }
}
```

`variables.tf`:

```hcl
variable "name" {
  type        = string
  description = "Bucket name. Must be globally unique."
  validation {
    condition     = can(regex("^[a-z0-9][a-z0-9.-]{1,61}[a-z0-9]$", var.name))
    error_message = "Bucket names: 3-63 chars, lowercase letters, digits, dots and hyphens."
  }
}

variable "versioning" {
  type        = bool
  description = "Keep previous versions of objects."
  default     = true
}

variable "kms_key_arn" {
  type        = string
  description = "KMS key for encryption. null = S3-managed keys (SSE-S3)."
  default     = null
}

variable "lifecycle_rules" {
  description = "Expire or transition objects."
  type = object({
    expire_days                = optional(number)          # null = never expire current objects
    noncurrent_expire_days     = optional(number, 90)
    transition_to_glacier_days = optional(number)
  })
  default = {}
}

variable "force_destroy" {
  type        = bool
  description = "Allow destroying a non-empty bucket. Keep false outside labs."
  default     = false
}

variable "tags" {
  type        = map(string)
  description = "Extra tags for the bucket."
  default     = {}
}
```

`main.tf`:

```hcl
resource "aws_s3_bucket" "this" {
  bucket        = var.name
  force_destroy = var.force_destroy
  tags          = var.tags
}

resource "aws_s3_bucket_versioning" "this" {
  bucket = aws_s3_bucket.this.id
  versioning_configuration {
    status = var.versioning ? "Enabled" : "Suspended"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "this" {
  bucket = aws_s3_bucket.this.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = var.kms_key_arn == null ? "AES256" : "aws:kms"
      kms_master_key_id = var.kms_key_arn
    }
    bucket_key_enabled = var.kms_key_arn != null
  }
}

resource "aws_s3_bucket_public_access_block" "this" {
  bucket                  = aws_s3_bucket.this.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_ownership_controls" "this" {
  bucket = aws_s3_bucket.this.id
  rule {
    object_ownership = "BucketOwnerEnforced"     # ACLs disabled
  }
}

data "aws_iam_policy_document" "tls_only" {
  statement {
    sid       = "DenyInsecureTransport"
    effect    = "Deny"
    actions   = ["s3:*"]
    resources = [aws_s3_bucket.this.arn, "${aws_s3_bucket.this.arn}/*"]
    principals {
      type        = "*"
      identifiers = ["*"]
    }
    condition {
      test     = "Bool"
      variable = "aws:SecureTransport"
      values   = ["false"]
    }
  }
}

resource "aws_s3_bucket_policy" "this" {
  bucket     = aws_s3_bucket.this.id
  policy     = data.aws_iam_policy_document.tls_only.json
  depends_on = [aws_s3_bucket_public_access_block.this]   # avoid a race between the two APIs
}

resource "aws_s3_bucket_lifecycle_configuration" "this" {
  bucket = aws_s3_bucket.this.id

  rule {
    id     = "default"
    status = "Enabled"
    filter {}

    dynamic "expiration" {
      for_each = var.lifecycle_rules.expire_days == null ? [] : [1]
      content {
        days = var.lifecycle_rules.expire_days
      }
    }

    dynamic "transition" {
      for_each = var.lifecycle_rules.transition_to_glacier_days == null ? [] : [1]
      content {
        days          = var.lifecycle_rules.transition_to_glacier_days
        storage_class = "GLACIER"
      }
    }

    noncurrent_version_expiration {
      noncurrent_days = var.lifecycle_rules.noncurrent_expire_days
    }
  }
}
```

- The optional-block trick from topic 23 (`for_each = cond ? [1] : []`) makes lifecycle rules optional.
- Every security setting is **on** and **not** an input: callers can't accidentally turn off TLS-only or public access blocking.

`outputs.tf`:

```hcl
output "id" {
  description = "Bucket name (the bucket's ID)."
  value       = aws_s3_bucket.this.id
}

output "arn" {
  description = "Bucket ARN, for IAM policies."
  value       = aws_s3_bucket.this.arn
}

output "regional_domain_name" {
  description = "Regional domain name, e.g. for CloudFront origins."
  value       = aws_s3_bucket.this.bucket_regional_domain_name
}
```

### Calling it

`~/tf-lab/44-module-use/main.tf` (with `versions.tf` + `provider "aws"` as in topic 31, `random` too):

```hcl
resource "random_id" "suffix" {
  byte_length = 3
}

module "bucket" {
  source   = "../modules/s3-secure-bucket"         # the module lives in ~/tf-lab/modules/
  for_each = {
    logs      = { expire_days = 30 }
    artifacts = { transition_to_glacier_days = 60 }
  }

  name            = "tf-course-${each.key}-${random_id.suffix.hex}"
  lifecycle_rules = each.value
  force_destroy   = true                           # lab only
  tags            = { purpose = each.key }
}

output "buckets" {
  value = { for k, m in module.bucket : k => m.arn }
}
```

### Anti-patterns

| Anti-pattern | Problem | Better |
|---|---|---|
| A module wrapping **one** resource and passing every argument through | Adds a layer without adding value | Use the resource directly, or add real opinions (defaults, security) |
| `provider` blocks inside the module | Breaks `for_each`, removal, multi-region | `required_providers` + `providers = {}` from the caller |
| 60 input variables with `enable_x` flags | Impossible to test; unclear what's supported | Smaller focused modules composed together (topic 47) |
| Data lookups by name inside the module (`data "aws_vpc" { tags = { Name = "main" } }`) | Hidden dependency on naming conventions | Take `vpc_id` as an input |
| Exact version pins in modules (`= 6.21.0`) | Conflicts with every caller's choice | Minimums: `>= 6.0` |
| Outputting whole resources | Callers depend on internals | Output specific attributes |
| Hard-coded region, account, names | Not reusable | Inputs or provider-derived values |

## When it breaks

| Error / symptom | Meaning | Fix |
|---|---|---|
| `Module is incompatible with count, for_each, and depends_on` | The module (or a nested one) has its own `provider` block. | Remove it; pass providers in. |
| `Provider configuration not present` after removing a module call | The module contained its provider config; destroying needs it. | Put the provider back in the root, apply the removal, then remove it. Avoid provider blocks in modules. |
| `No configuration for provider aws.replica` / `missing provider` | The module declares `configuration_aliases` but the caller didn't pass it. | `providers = { aws.replica = aws.<alias> }`. |
| Provider version conflict on `init` | The module pins tightly (`= x` or `< y`). | Use minimum constraints in modules. |
| Every caller had to change after a module update | A breaking input/output change. | Version modules and follow SemVer (topic 45); use `moved` blocks inside the module. |

## Quick recap

- Layout: `versions.tf`, `variables.tf`, `main.tf`, `outputs.tf`, `README.md`, `examples/`, `tests/`.
- Inputs: few, typed, validated, `optional()` defaults, **secure by default**; pass IDs in.
- Outputs: specific attributes with descriptions.
- **No `provider` blocks** in modules; minimum `required_providers`; aliases via `configuration_aliases` + `providers = {}`.
- Document with terraform-docs; avoid one-resource wrappers and flag soup.

### Interview questions

1. **Q: How do you design a good reusable module?**
   A: A small, focused purpose; few typed and validated inputs with secure defaults; specific, documented outputs; minimum provider versions and no provider blocks; examples, tests, a README and semantic versioning.
2. **Q: Why shouldn't a module contain provider blocks?**
   A: It ties the module to one configuration, prevents `count`/`for_each`/`depends_on` on the module, and makes removing the module break because the provider config disappears with the resources. Callers should configure providers and pass them in.
3. **Q: How does a module use two AWS regions?**
   A: It declares `configuration_aliases = [aws.replica]` in `required_providers` and uses `provider = aws.replica` on resources; the caller maps its own aliased provider with `providers = { aws.replica = aws.<alias> }`.
